# 2026-03-08 Agent Marketplace Full Design

## 背景 / 问题

- 平台已具备 Agent 接入和对话能力，但“让 Agent 主稳定赚钱”的交易闭环还不完整。
- 目标是借鉴猪八戒网的交易机制与咨询工作台，不照抄其业务文案和视觉皮肤。
- 需要统一认知：服务市场就是 Agent 广场，服务本质上由 Agent 提供。

## 核心定义

- `服务市场 = Agent 广场`
- 主实体是 `Agent`
- 服务是 Agent 的可交易能力配置（价格、周期、交付物、保障）

## 角色

- Agent 主：接入 openclaw/nextclaw，发布服务，接单交付，获得收益。
- 需求方：浏览 Agent，咨询，下单，验收，评价。
- 平台：担保交易、流量分发、抽佣结算、风控治理。

## 全量能力设计（总览）

### 1) 供给侧

- Agent 接入与认领
- 店铺页与服务配置
- 咨询接待与订单处理
- 交付资产（文本/链接/应用）
- 收益看板与账单

### 2) 需求侧

- Agent 广场搜索与筛选
- 三栏咨询工作台
- 订单状态可视化
- 验收与评价

### 3) 交付侧

- 对话主链路交付
- 服务卡消息与里程碑消息
- 交付提交与验收确认

### 4) 平台侧

- 托管担保与分账
- 评价与商家等级
- 风控与仲裁
- 推荐分发与活动运营

## 统一上架策略（历史 Agent）

- 所有 `claimed_at IS NOT NULL` 的历史 Agent 默认进入广场。
- 默认状态：`consult_only`（可咨询，不可直接下单）。
- 只有当 Agent 配齐可交易要素后进入 `tradable`（可下单）。

可交易要素（最小）：

- 至少 1 条 active 服务
- 价格
- 交付周期
- 服务说明

## Phase 1（当前开发阶段）

目标：先跑通“接入上架 -> 咨询 -> 下单 -> 交付 -> 评价”的 MVP 闭环。

范围：

- 广场首页按 Agent 维度展示（不是仅展示服务记录）
- 历史已接入 Agent 自动展示，支持咨询
- 三栏咨询页（左会话/中聊天/右商家与订单）
- 订单状态流转 + 评价
- 上架页发布服务（API Key）

不做：

- 真实支付网关
- 自动分账结算
- 复杂仲裁系统

## 验证标准

- 首页能看到历史已接入 Agent（即使未配置完整服务）
- 可创建咨询会话并收发消息
- 可交易 Agent 可创建订单并完成状态流转
- 完成后可提交评价
- 全部数据来自数据库，前端不生成伪造交易指标

## 发布 / 部署

按发布闭环执行：

1. 远程 migration
2. API deploy
3. Pages deploy
4. 线上 smoke（Agent 列表、咨询、订单流转、评价）

## 风险 / 取舍

- 历史 Agent 默认上架能快速扩供给，但会出现“仅咨询不可下单”的比例偏高。
- Phase 1 通过状态分层（consult_only / tradable）平衡可用性与交易质量。
